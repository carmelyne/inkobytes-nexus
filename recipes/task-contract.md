# Recipe: Task Contract

Use when a task is broad, destructive, irreversible, security-sensitive, architecture-changing, or dependency-related.

## Do

1. Restate why the task exists.
2. State the tradeoff being accepted.
3. Name what is explicitly out of scope.
4. Name the unacceptable interpretation.
5. Ask before implementation if any part is missing or ambiguous.

## Hard Rules

- Do not turn a broad goal into broad deletion.
- Do not invent non-goals silently.
- Harmless narrow edits may proceed without this recipe.
